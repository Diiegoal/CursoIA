# 🎥 Prompt engineering para ciberseguridad 🔴 — 53 min

Daniel Zaragoza

⏳ Tiempo estimado: 53 min

En esta sección mostramos algunos ejemplos rápidos que ilustran cómo con un conocimiento de alto nivel de las prácticas de ciberseguridad más relevantes (presentadas anteriormente), y sabiendo qué preguntar al asistente, podemos tener código menos vulnerable con el mismo esfuerzo:

## Te hace estar aware de las vulnerabilidades de tu código, ideal para extender el conocimiento de los developers en el area de seguridad. Preguntas del tipo:

“¿Es este codigo seguro?”

“Lista las vulnerabilidades que encuentras”,

## Incorporar por defecto medidas de seguridad en los requisitos no funcionales y los criterios de aceptación de los desarrollos. Por ejemplo:

“Eres un experto en ciberseguridad. Dada la historia de usuario a continuación, añade los criterios de aceptación o requisitos no funcionales necesarios para garantizar la seguridad de la aplicación acorde a las mejores prácticas de ciberseguridad, y en concreto OWASP top 10. Limítate a mencionar aquellos específicos de la historia de usuario, obviando los que puedan ser de nivel de aplicación, tales como autenticación, roles y permisos, encriptación de los datos en tránsito, que lo trabajamos a nivel global.”

## Le podemos pedir que siga el framework OWASP (Open Worldwide Application Security Project) para proponer soluciones concretas que apliquen en nuestro código

“Acorde al framework OWASP top 10, detecta las vulnerabilidades más importantes de @backend, dame ejemplos concretos para justificarlo y propón soluciones a cada una de ellas. Hasta que no terminemos con una no comiences con la siguiente”

## A partir de ahí te puede ayudar encontrando bugs concretos, proponiendo ejemplos para fuzzy testing e incluso generando el script para probarlos

“¿Cómo lo soluciono?”

“Propón código para solucionar cada una de las vulnerabilidades encontradas”

## Actualización 2026: del prompting manual al Agent Mode

Los prompts manuales de esta sección siguen siendo válidos como fundamento, pero hoy las herramientas con Agent Mode (Claude Code, Cursor) mitigan en gran parte la limitación de "falta de contexto" que se menciona en el vídeo: pueden leer todos los archivos del proyecto y proponer correcciones contextualizadas en lugar de genéricas. Pruébalo ahora con tu proyecto abierto en Claude Code o Cursor con un prompt como este:

"Eres un experto en ciberseguridad. Analiza todo el backend de este proyecto aplicando el OWASP Top 10:2025 (web) y el OWASP Top 10 para aplicaciones LLM (2025). Para cada vulnerabilidad: (1) muestra el código vulnerable, (2) explica el riesgo y (3) propón el código corregido. No empieces con la siguiente hasta cerrar la anterior y prioriza por criticidad."

Complementan este enfoque las plataformas que ya detectan y autocorrigen dentro del flujo de trabajo: GitHub Copilot Autofix (genera correcciones directamente en los Pull Requests) y Snyk con DeepCode AI (análisis semántico consciente del contexto). Encontrarás el detalle de las dos listas OWASP que referencia el prompt en la sección de buenas prácticas y frameworks de seguridad.
