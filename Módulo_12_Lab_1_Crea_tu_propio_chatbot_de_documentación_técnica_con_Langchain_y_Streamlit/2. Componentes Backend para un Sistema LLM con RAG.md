En este artículo exploraremos en detalle los componentes backend esenciales para construir un sistema LLM con RAG. Nos centraremos en cuatro piezas: el framework de orquestación (LangChain), el modelo codificador (all-MiniLM-L12-v2), el LLM (Gemma-2b-it) y la plataforma que aloja los modelos (Hugging Face). Cerramos con una mención a Ollama, herramienta estándar para ejecutar LLMs localmente.

# 1. LangChain
LangChain es una biblioteca de Python (también disponible en JavaScript/TypeScript) diseñada para facilitar la construcción de aplicaciones que requieren procesamiento y generación de texto con LLMs. Es especialmente útil para crear sistemas que integran múltiples componentes, como modelos de lenguaje, modelos codificadores y bases de datos vectoriales.

## LangChain v1.0 — el cambio mayor del último ciclo
LangChain alcanzó la v1.0 el 22 de octubre de 2025, marcando su madurez como framework después de tres años de v0.x con breaking changes constantes. El compromiso público es no introducir breaking changes hasta v2.0.

### Los cambios estructurales más relevantes:

create_agent reemplaza a las antiguas abstracciones de chains/agents. Es la forma idiomática de construir un agente con cualquier proveedor de modelo, construida sobre el runtime de LangGraph.

Sistema de middleware: control fine-grained en cada paso del agent loop. Trae middlewares listos para human-in-the-loop, summarization y redacción de PII.

langchain-classic: las abstracciones legacy (LLMChain, RetrievalQA, etc.) se han movido a este paquete separado. Si encuentras código antiguo con from langchain.chains import RetrievalQA, hay que cambiarlo a from langchain_classic.chains import RetrievalQA o, preferiblemente, migrar a la nueva API.

Mensaje estandarizado con .content_blocks: nuevo modelo de bloques de contenido (text, reasoning, citations, tool_calls) que permite portabilidad real entre proveedores.

Python 3.10+ obligatorio (Python 3.9 quedó descontinuado en línea con su EOL de octubre 2025).

## Características Clave de LangChain v1.0
Integración de modelos: integración sencilla con OpenAI, Anthropic, Google, Hugging Face, Ollama y proveedores locales.

Manejo de documentos: herramientas para cargar, dividir y procesar documentos de manera eficiente, incluyendo las estrategias de chunking que vimos en la sección 1.

Búsqueda y recuperación: funciones para realizar búsquedas híbridas y recuperar información relevante de bases de datos vectoriales.

LangGraph: framework complementario para definir flujos de trabajo complejos como grafos de estado, ideal para construir Agentic RAG, CRAG y patrones similares.

LangSmith: plataforma de observabilidad para monitorizar, depurar y evaluar aplicaciones LLM en producción.

## LangGraph 1.0
Promovido a 1.0 en el mismo evento (22 oct 2025) sin breaking changes, LangGraph se ha consolidado como el runtime de facto para agentes en 2026. Casos de uso reales documentados oficialmente: Uber, LinkedIn, Klarna. Aporta:

Estado durable: el estado del agente persiste automáticamente. Si el servidor cae, el agente continúa desde el último checkpoint.

Human-in-the-loop nativos.

Streaming de tokens y de pasos intermedios.

Memoria a corto plazo integrada.

## Alternativa: LlamaIndex
LlamaIndex es el otro framework Python de referencia, especializado en RAG. Ventajas concretas frente a LangChain para casos de uso puramente de retrieval:

Produce 30–40% menos código para un pipeline RAG equivalente.

Hierarchical chunking, auto-merging retrieval y sub-question decomposition de fábrica.

300+ conectores de datos (LlamaHub).

Menor overhead medido (~6 ms vs ~14 ms de LangGraph) en benchmarks comparativos.

Cuándo usar cuál: si solo necesitas RAG, LlamaIndex es objetivamente más conciso. Si vas a añadir agentes y orquestación compleja, vale la pena empezar con LangChain + LangGraph para reutilizar conocimiento. Muchos sistemas de producción los combinan: LlamaIndex como capa de retrieval, LangGraph como capa de orquestación.

# 2. Modelo Codificador: all-MiniLM-L12-v2
El modelo all-MiniLM-L12-v2 es un modelo codificador basado en la arquitectura Transformer, diseñado para generar embeddings de texto compactos y de alta calidad, esenciales para realizar búsquedas eficientes y precisas en bases de datos vectoriales.

## Características Clave del all-MiniLM-L12-v2
Tamaño compacto: relativamente pequeño en comparación con otros modelos de embeddings, lo que permite procesamiento rápido y eficiente en hardware modesto (incluso en CPU).

Embeddings de alta calidad: genera representaciones numéricas de 384 dimensiones que capturan relaciones semánticas, facilitando la recuperación de información relevante.

Contexto: 256 tokens (~200 palabras), suficiente para chunks pequeños.

## ⚠ Limitaciones a tener en cuenta (2026)
all-MiniLM-L12-v2 fue publicado en 2021 y es monolingüe inglés. Para un laboratorio educativo introduce los conceptos correctamente, pero su rendimiento en español es claramente inferior a las alternativas modernas. Para proyectos reales, considera:

| Modelo | Tamaño | Idiomas | Notas |
|---|---|---|---|
| **BAAI/bge-m3** | ~560M | 100+ (incl. español) | MIT, 8K tokens, dense+sparse en una pasada. Caballo de batalla open-source. |
| **google/embeddinggemma-300m** | 300M | 100+ | Apache 2.0. Derivado de Gemma 3, excelente relación tamaño/rendimiento. |
| **Qwen3-Embedding-8B** | 8B | 100+ | 70,58 en MTEB. **Mejor opción open-source para RAG multilingüe self-hosted en 2026.** |
| **Cohere Embed v4** | API | 100+ | Propietario. 128K contexto. Robusto en datos ruidosos. |
| **Gemini Embedding 001** | API | 100+ | **Líder MTEB inglés (68,32).** |
| **Gemini Embedding 2 (Preview)** | API | 100+ | Lanzado 10 marzo 2026. Primer embedding all-modality (texto, imagen, video, audio, PDF). |

NVIDIA Llama-Embed-Nemotron-8B (octubre 2025) es la opción gratuita más potente para aplicaciones globales/multilingües. Voyage AI fue adquirida por MongoDB en febrero 2025 y mantiene Voyage 3.5 como opción comercial sólida.

# 3. LLM: Gemma-2b-it
Gemma-2b-it es un modelo de lenguaje grande (LLM) desarrollado por Google, perteneciente a la familia de modelos Gemma. Los modelos Gemma son ligeros y de alto rendimiento, diseñados para tareas de generación de texto, comprensión del lenguaje y razonamiento lógico. Fueron creados utilizando la misma investigación y tecnología que los modelos Gemini, y están diseñados para ser eficientes y versátiles. La variante -it (instruction-tuned) está optimizada para seguir instrucciones, lo que la hace ideal para chatbots y sistemas de Q&A como nuestro RAG.

https://www.youtube.com/watch?v=OMyTQzjLZDk&t

## Evolución de la familia Gemma (2024-2026)

La familia Gemma ha evolucionado significativamente desde el modelo original que usaremos en el laboratorio:

Gemma 2 (junio 2024): la generación que incluye el gemma-2b-it que usaremos. Texto puro, contexto de 8K tokens.

Gemma 3 (marzo 2025): primera versión multimodal (texto, imagen, video, audio en variantes 4B+), 128K tokens de contexto, 140+ idiomas. Tamaños 1B, 4B, 12B, 27B + 270M y 3n.

Gemma 4 (lanzado el 2 de abril de 2026): última generación. Apache 2.0. Variantes E2B, E4B, 26B-A4B (MoE) y 31B dense. Multimodal nativo, system prompt nativo, contexto 128K (E2B/E4B) hasta 256K. Score LMArena estimado 1452 (31B) / 1441 (26B MoE).

Para el laboratorio: Gemma-2b-it sigue siendo válido pedagógicamente por su tamaño y simplicidad, y es lo que vamos a usar. Para proyectos reales en 2026, considera los reemplazos directos:

| Caso | Reemplazo recomendado |
|---|---|
| Sustituto directo (texto, ~1B params, T4 sin cuantizar) | `google/gemma-3-1b-it` |
| Multimodal y multilingüe en T4 (4-bit) | `google/gemma-3-4b-it` o `google/gemma-4-e2b-it` |
| Mejor rendimiento en español a tamaño comparable | `Qwen2.5-7B-Instruct` o `Qwen3-4B/8B` (4-bit) |
| Reasoning didáctico (cadena de pensamiento visible) | `DeepSeek-R1-Distill-Qwen-7B` |
| Scale producción / razonamiento avanzado | **DeepSeek V3.2 (685B MoE)**, **Llama 4 Scout (10M tokens contexto)** |
| Modelo europeo open | **Mistral Small 3.1 (24B)** |

# Hugging Face: el Hub de la IA Open Source
Hugging Face es la plataforma líder para alojar y compartir modelos de aprendizaje automático. Ofrece más de 1 millón de modelos preentrenados, herramientas de desarrollo y una comunidad activa de investigadores y desarrolladores.

## Características Clave de Hugging Face (2025-2026)
Modelos preentrenados: acceso a toda la familia Gemma (incluida Gemma 4), embeddings como BGE-M3, codificadores como all-MiniLM-L12-v2 y miles más.

Transformers v5: liberada a finales de 2025 (RC0 en diciembre, estable poco después). v5.4.0 disponible en abril 2026. Punto de entrada from_pretrained ahora unifica paralelismo, cuantización, kernels custom, flash/paged attention y continuous batching. ⚠ Breaking changes importantes: HTTP backend cambia de requests a httpx, varias tasks de pipeline renombradas, hf_transfer reemplazado por hf_xet. Si trabajas con código pre-v5, revisa el migration guide oficial.

huggingface_hub v1.0: liberada conjuntamente con Transformers v5. Cinco años después del v0.0.1.

Spaces: plataforma para desplegar aplicaciones de IA (Gradio o Streamlit) directamente desde el Hub. ZeroGPU ahora corre sobre NVIDIA H200 (70 GB VRAM) y permite ejecutar modelos open-source sin pagar por GPU dedicada.

Inference Providers: servicio managed para llamadas serverless a modelos del hub. Free tier 100K créditos/mes; PRO ($9/mes) sube a 2M créditos.

# 4. Ejecución local con Ollama
Ollama se ha convertido en la herramienta estándar para ejecutar LLMs localmente sin depender de APIs externas. Hitos relevantes:

App de escritorio nativa para macOS y Windows desde el 30 de julio de 2025 (antes solo CLI).

Tool calling soportado en modelos compatibles (Qwen 3, Llama 3.1+, Mistral, DeepSeek V3.1, etc.). Documentación oficial en docs.ollama.com/capabilities/tool-calling.

Ollama Cloud: opción para servir modelos grandes (deepseek-v3.1:671b-cloud, llama4:cloud) que no caben en hardware local, con la misma API.

MCP (Model Context Protocol): la UI desktop aún no lo soporta nativamente (issue abierto), pero hay clientes externos (ollmcp, ollama-mcp) que conectan Ollama con servidores MCP.

Ejemplo de uso para experimentar localmente con la familia Gemma actual:

ollama run gemma3:4b
# o, ya con Gemma 4:
ollama run gemma4:e2b
## Alternativas en el ecosistema local:

LM Studio: mejor UI gráfica para descubrir modelos. Sin tool calling/MCP equivalente.

vLLM: opción de producción para alta concurrencia (continuous batching, paged attention). Soportado oficialmente como runtime de Transformers v5.

llama.cpp / GGUF: capa subyacente que usa Ollama por debajo. Útil para entender que "no es magia".
