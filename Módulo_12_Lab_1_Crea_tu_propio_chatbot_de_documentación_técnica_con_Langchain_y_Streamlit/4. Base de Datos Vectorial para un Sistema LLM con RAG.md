En esta sección exploraremos el uso de bases de datos vectoriales, una pieza crucial para construir un sistema LLM con RAG. Nos enfocaremos en FAISS, biblioteca desarrollada por Meta para búsqueda eficiente por similitud, que es la que utilizaremos en el laboratorio. También revisaremos las alternativas relevantes en 2026: ChromaDB, Qdrant, Pinecone, Weaviate, Milvus, pgvector y Neo4j.

# 1. FAISS (usado en el laboratorio)
FAISS (Facebook AI Similarity Search) es una biblioteca de software desarrollada por Meta AI Research para realizar búsquedas eficientes en grandes colecciones de vectores. Es especialmente útil para tareas de recuperación de información donde la velocidad y la precisión son esenciales.

## Características Clave de FAISS
Eficiencia: extremadamente rápido en búsqueda por similitud gracias a técnicas avanzadas de indexación (HNSW, IVF, PQ y combinaciones).

Escalabilidad: maneja millones de vectores con facilidad. Soporta GPU para acelerar todavía más.

Versatilidad: múltiples tipos de índice permiten elegir la estructura que mejor se adapte al caso de uso (precisión vs. memoria vs. velocidad).

Compatibilidad: integración directa con LangChain, LlamaIndex y otros frameworks RAG.

## ⚠ Nota importante: FAISS es una biblioteca, no una base de datos
FAISS no incluye persistencia automática, API REST, multi-tenancy ni filtrado avanzado por metadatos. Es ideal para prototipos y laboratorios porque su transparencia algorítmica permite entender qué está pasando bajo el capó. Para producción conviene una base de datos vectorial completa (ChromaDB, Qdrant, pgvector, etc.).

# 2. ChromaDB
ChromaDB es una base de datos vectorial open-source que se ha consolidado como una de las opciones más populares para RAG didáctico y prototipos.

## El gran cambio: reescritura en Rust (2025)
ChromaDB lanzó Chroma 1.0.0 GA en abril de 2025, completando la reescritura de su core de Python a Rust. La versión actual a abril 2026 es 1.5.7 (con releases mensuales). Las mejoras medidas son significativas:

3–5× más rápido en escrituras y ~4× más rápido en consultas.

Multithreading real sin el bottleneck del GIL.

Nuevo motor de ejecución push-based morsel-driven (agosto 2025).

70% mejora en throughput vía base64 vector encoding (julio 2025).

Búsqueda por regex (junio 2025) y filtros array metadata $contains/$not_contains (febrero 2026).

## Características Clave de ChromaDB
API simple: interfaz Python sencilla, ideal para prototipado rápido.

Persistencia incluida: a diferencia de FAISS, maneja la persistencia automáticamente con chromadb.PersistentClient(...).

Filtrado por metadatos: combina filtros estructurados con búsqueda vectorial.

Integración nativa: compatible con LangChain, LlamaIndex y otros frameworks.

## ⚠ Breaking changes en v1.0: Chroma ya no incluye implementaciones built-in de autenticación; la configuración del servidor pasó a archivo de configuración. Si encuentras código de v0.x, revisa el migration guide oficial.

Más información en trychroma.com.

# 3. Qdrant
Qdrant es una base de datos vectorial escrita en Rust desde el inicio, orientada a producción.

## Características Clave
Filterable HNSW: filtra por metadatos durante el recorrido del grafo, no después. Resultado: latencias mucho mejores cuando se combinan filtros con búsqueda vectorial.

Distribuida y ACID.

Búsqueda híbrida nativa (vectorial + keyword) en una sola query.

Asymmetric quantization con compresión hasta 24× (2025).

Hybrid Cloud, RBAC OAuth2/OIDC, GPU acceleration en versiones recientes.

Es la mejor opción open-source self-hosted para producción sin vendor lock-in.

# 4. Pinecone
Pinecone es la opción managed serverless líder del mercado empresarial.

## Características Clave
Serverless (no pods): escala automática y precio por uso real.

Cero ops: ideal para equipos que no quieren gestionar infraestructura.

Pinecone Rerank V0 (2025): cross-encoder propio integrado en el producto, hasta 512 tokens.

Pricing aproximado: tier gratuito 100K vectores; planes desde ~$70/mes para volúmenes pequeños; ~$200–400/mes para 10M vectores [⚠ verificar pricing actual en pinecone.io].

# 5. Weaviate
Weaviate es una base de datos vectorial open-source con foco en multimodalidad y módulos de vectorización integrados.

## Características Clave
Búsqueda híbrida nativa (BM25 + vector con una sola query).

Módulos de vectorización integrados: insertas texto y Weaviate vectoriza por ti (con CLIP, ImageBind o embeddings externos).

Multimodal: texto, imágenes, audio, video.

GraphQL como interfaz de query.

Cloud managed con sandbox gratuito.

Buena elección cuando quieres "insertar y olvidar" sin gestionar el embedding tú mismo.

# 6. Milvus
Milvus es el veterano para escalabilidad masiva (billones de vectores). Open-source, distribuido, con GPU acceleration disponible. Su versión managed se llama Zilliz Cloud.

Para casos donde Qdrant o Weaviate se quedan cortos. No es opción para laboratorio educativo por su complejidad operativa, pero es importante tenerlo en el radar para escala empresarial extrema.

# 7. pgvector
pgvector es una extensión de PostgreSQL que añade búsqueda vectorial nativa. En 2026 es el estándar de facto para casos simples y medios, especialmente cuando ya hay Postgres en la organización.

## Ventajas decisivas
Vectores y datos relacionales en el mismo sistema: una sola transacción, una sola infraestructura, una sola fuente de la verdad.

Cero vendor lock-in adicional si ya usas Postgres.

Joins entre datos vectoriales y relacionales sin malabares.

## Limitaciones reales
Por encima de 50–100M vectores, throughput y latencia quedan por debajo de DBs vector-purpose-built. Para el 90% de los proyectos enterprise reales, pgvector es suficiente.

# 8. Neo4j Vector Index
Neo4j es una base de datos de grafos que permite modelar y gestionar datos altamente conectados. Ha ganado nueva relevancia con el auge de GraphRAG (variante explicada en la sección 1).

## Características Clave de Neo4j (2026)
Modelado de grafos: ideal para relaciones complejas entre entidades.

Neo4j Vector Index: soporte nativo para búsqueda vectorial, permitiendo combinar consultas de grafos con búsqueda semántica en una sola query.

Pieza clave de GraphRAG: la integración estándar con LangChain (Neo4jVector, GraphCypherQAChain) y LlamaIndex hace que sea la elección por defecto cuando el caso de uso requiere razonamiento multi-hop sobre entidades.

Más información en neo4j.com.

# 9. Tabla comparativa: ¿cuál elegir según el caso?

| Caso de uso | Elección recomendada | Por qué |
|---|---|---|
| Laboratorio educativo / notebook | FAISS o ChromaDB | FAISS es transparente; Chroma persistente y 4× más rápido tras Rust rewrite |
| Prototipo Python local con persistencia simple | **ChromaDB 1.x** | `pip install`, persistencia, filtros |
| Producción con Postgres existente | **pgvector** | Una sola infra, ACID con datos relacionales |
| Producción self-hosted exigente | **Qdrant** | Mejor latencia/throughput open-source |
| Producción managed serverless | **Pinecone** | Cero ops, escala automática |
| Multimodal con vectorización integrada | **Weaviate** | Inserta texto y vectoriza solo |
| Escala masiva (billones de vectores) | **Milvus** | Único probado a esa escala |
| GraphRAG / razonamiento multi-hop | **Neo4j Vector** | Grafo + vector nativo |
