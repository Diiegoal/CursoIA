**Lia Carrizo**

⏳ Tiempo estimado: 26 min

## De diseño a código con IA en 2026

El área más vistosa de la IA aplicada al desarrollo sigue siendo el frontend. Pero lo que era "generar una web desde un prompt o una captura" en 2023-2024 hoy es solo la punta del iceberg: el flujo profesional ha pasado de "screenshot → GPT-Vision → código" a algo mucho más rico, donde tres piezas conviven en un mismo workflow:

- **Agentes integrados en tu IDE o terminal** (Cursor 3, Claude Code, GitHub Copilot agent mode, Windsurf), capaces de leer tu codebase, abrir un navegador, tomar capturas e iterar el resultado.
- **MCP (Model Context Protocol) como protocolo común entre el diseño y el código:** Figma Dev Mode MCP, shadcn MCP, Chrome DevTools MCP, Playwright MCP. Tu agente ya no "adivina" el diseño desde una imagen: lo lee estructurado.
- **Plataformas full-stack de vibe coding** (v0.app, Lovable, Bolt.new, Replit Agent, Figma Make, Claude Design) que generan apps enteras en minutos y se han consolidado como la vía rápida para MVPs y prototipos clicables.

El stack output que producen todas estas herramientas en 2026 converge prácticamente en lo mismo: React 19 + Next.js 15/16 + Tailwind CSS v4 + shadcn/ui + TypeScript. Esa convergencia es la mejor noticia para ti como dev senior: lo que aprendes en una herramienta te sirve en las otras.

Esta sesión es 100% hands-on. Al terminar la sesión async ya deberías haber instalado al menos un MCP server y haber regenerado un componente desde un Figma o screenshot. En la sesión en vivo cerramos el loop con un caso real.

## El mapa del territorio (qué usar y cuándo)

Antes de bajar al detalle, quédate con este mapa mental. Cada categoría resuelve un problema distinto y cobran sentido en momentos distintos del ciclo de desarrollo.

| Categoría | Qué resuelve | Herramientas líderes 2026 | Caso de uso típico |
|---|---|---|---|
| **IDE agénticos** | Trabajar con código existente, refinar, integrar | Cursor 3, Claude Code, GitHub Copilot, Windsurf | "Tengo un repo y necesito implementar/refinar UI sin perder consistencia" |
| **Plataformas vibe coding** | Arrancar de 0, MVPs, prototipos clicables | [v0.app](https://v0.app), Lovable, [Bolt.new](https://bolt.new), Replit Agent | "No tengo nada y necesito algo demoeable mañana" |
| **Figma-native** | Handoff diseño → código estructurado | Figma Dev Mode MCP + Code Connect, Figma Make, [Builder.io](https://builder.io) | "El equipo de diseño trabaja en Figma y quiero código fiel a tokens" |
| **Visual / prototipado IA** | Wireframes y mockups conceptuales | Google Stitch (ex-Galileo AI), Uizard, Visily, Claude Design | "Necesito explorar opciones visuales antes de decidir" |

Los tres casos de uso clásicos siguen siendo válidos, pero se mapean a categorías distintas:

- **Implementar UI sobre web/app existente** → IDE agéntico + Figma MCP. Es el caso más común en empresa y donde más valor aporta dominar el flujo.
- **Empezar un proyecto desde 0** → vibe coding (v0/Lovable/Bolt) + exportar a GitHub para seguir en el IDE.
- **No eres frontend pero necesitas UI** → vibe coding como pair programmer visual, o Claude Code/Cursor con shadcn/ui directamente.

## Bloque 1: IDE agénticos (donde vive el dev senior)

### Cursor

Cursor es probablemente el IDE agéntico con mayor adopción profesional en 2026 (~$2B ARR reportado en marzo 2026). Versión actual: Cursor 3 (lanzado el 2 de abril de 2026), tras Cursor 2.0 (29 de octubre de 2025).

Lo que importa para diseño-a-código:

- **Composer 2:** modelo propio entrenado con RL on-policy, ~200 tokens/segundo, 61.3 en CursorBench (+39% sobre Composer 1.5). Útil para iteraciones UI rápidas.
- **Design Mode** (re-introducido en Cursor 3): área dedicada al trabajo UI-heavy, con previsualización integrada.
- **Agents Window:** workspace para correr múltiples agentes en paralelo (hasta 8 con Cursor 2.0; multi-task con subagents en versiones 3.x).
- **Browser tool nativo:** el agente puede abrir una vista del navegador, seleccionar elementos y forwardear el DOM al modelo. Esto convierte a Cursor en un loop diseño-código sin salir del IDE.
- **MCP servers de un click:** Figma, Chrome DevTools, Playwright, shadcn instalables desde la UI.

Pricing 2026: Free (~50 slow requests/día), Pro $20/mes, Max $200/mes (cloud agents y prioridad GPU).

> **Prueba esto ahora (15 min):** instala Cursor → abre un proyecto React → en Settings activa el MCP server de Figma → en el chat pega un link a un frame de Figma y pídele que genere el componente con Tailwind v4.

### Claude Code

Es la herramienta de demo por defecto del máster. En 2026 es uno de los tres líderes del segmento agéntico junto a Cursor y Copilot.

Características relevantes para diseño-a-código:

- **Modelo de visión potente:** Claude Opus 4.7 (lanzado en abril 2026) acepta imágenes hasta 2576 px en el lado largo (~3.75 MP, 3× más que Opus 4.6). Anthropic lo posiciona específicamente para "dashboards e interfaces ricas en datos" (afirmación de marketing, citada como tal).
- **Ventana de contexto:** 1M tokens en Sonnet 4.6 vía API. Suficiente para meterle el codebase entero de la mayoría de proyectos.
- **Skills:** plugins reutilizables que activan flujos especializados.
- **Plugin oficial de Figma para Claude Code:** instalable con `claude plugin install figma@claude-plugins-official`. Da acceso al Figma Dev Mode MCP server con sintaxis nativa.
- **Claude Design** (Anthropic Labs, research preview lanzada el 17 de abril de 2026): compañero de Claude Code orientado a prototipos visuales (slides, decks, marketing assets, prototipos React). Genera código exportable a HTML/PPTX/Canva/PDF, con handoff bundle directo a Claude Code. Disponible para usuarios Claude Pro/Max/Team/Enterprise.

Pricing 2026 (verificado en claude.com/pricing en abril 2026):

- Claude Pro $20/mes (incluye uso de Claude Code con límites)
- Claude Max 5x $100/mes
- Claude Max 20x $200/mes
- API pay-as-you-go: Sonnet 4.6 ($3 input / $15 output por MTok), Opus 4.7 ($5 / $25), Haiku 4.5 ($1 / $5)

> ⚠ **Aviso:** el 21–22 de abril de 2026 Anthropic hizo un test (2% usuarios) moviendo Claude Code fuera del plan Pro; revertido tras protesta pública. La política oficial actual lo mantiene en Pro $20. Verifica antes de comprar plan.

> **Prueba esto ahora (20 min):** instala Claude Code → ejecuta `claude plugin install figma@claude-plugins-official` → conecta tu cuenta de Figma → pega un node-link y pídele un componente React con shadcn/ui.

### GitHub Copilot

El más adoptado por inercia y por integración nativa con GitHub Enterprise.

Estado en abril 2026:

- Agent mode GA en VS Code y JetBrains (marzo 2026).
- Coding agent autónomo: le asignas un issue y abre un PR completo con cambios + tests.
- Code review agéntico sobre PRs (marzo 2026).
- GitHub Spark (Pro+/Enterprise): describe app en lenguaje natural, código generado con preview en vivo.
- Soporta MCP nativamente. La documentación oficial de GitHub describe un flujo combinando Figma MCP + GitHub MCP + Playwright MCP para auditorías de accesibilidad — receta directamente reutilizable en clase.

Pricing 2026: Free (50 premium requests/mes), Pro $10/mes, Pro+ $39/mes, Business $19/usuario/mes, Enterprise $39/usuario/mes. Overage $0.04/premium request.

> ⚠ **Crisis de capacidad abril 2026:** GitHub pausó nuevos signups de Pro/Pro+/Student el 20 de abril de 2026 por sobreconsumo en workflows agénticos. Si no tienes ya cuenta, valora alternativas hasta que se reabran.

### Windsurf

Adquirido por Cognition (creadores de Devin) en julio de 2025 tras un drama de varios meses (Google se llevó al CEO + cofundadores por $2.4B en acquihire, OpenAI canceló su oferta de $3B). Cognition pasó a estar valorada en $10.2B dos meses después.

Sigue siendo un IDE agéntico sólido con Cascade (multi-step edits), Tab y Supercomplete, e integra Devin como agente autónomo dentro del IDE. Posicionamiento en 2026: tercera opción detrás de Cursor y Claude Code, pero con argumentos para equipos enterprise (350+ enterprise customers, $82M ARR pre-adquisición).

Pricing: Pro ~$20/mes; ha sufrido varios reajustes de cuota en 2025-2026.

## Bloque 2: plataformas full-stack "vibe coding"

### v0 (v0.app)

Rebrand v0.dev → v0.app en enero 2026. La actualización de febrero 2026 la convirtió en una plataforma full-stack: editor estilo VS Code, Git integrado, conexión a bases de datos (Snowflake, AWS) y workflows agénticos. Ya no es solo un generador de componentes.

- Genera React + Next.js + Tailwind v4 + shadcn/ui por defecto. Es la herramienta con la mejor calidad UI según la mayoría de comparativas independientes.
- Soporta imagen-a-código y, en el plan de pago, Figma imports nativos.
- Integración profunda con shadcn: cualquier componente de ui.shadcn.com tiene un botón "Open in v0". Es el flujo recomendado por shadcn oficialmente.

Pricing 2026: Free ($5 en créditos), Premium $20/mes (+$20 en créditos, Figma imports y API access), Team $30/usuario/mes, Business $100/usuario/mes. Modelo token-based desde febrero 2026.

### Lovable

Llegó a $20M ARR en 2 meses (récord europeo). Su diferenciador: es full-stack real, con integración nativa Supabase (DB + auth + storage + edge functions), one-click deployment y sync bidireccional con GitHub.

- Agent Mode (autónomo), Chat Mode (colaborativo) y Visual Edits (manipulación click-to-edit).
- El usuario es dueño del código generado (lo dice en sus ToS).

Pricing 2026: Free (5 créditos/día, ~30/mes); Pro $25/mes (100 créditos + 5/día, compartido sin límite de usuarios); Business $50/mes (SSO, RBAC); Enterprise custom.

### Bolt.new (StackBlitz)

~$40M ARR en 6 meses. Corre sobre WebContainers (browser-based, cero setup local). Más cercano a un IDE en el navegador que Lovable: terminal completa, file tree, elección de modelo (Claude Opus 4.6/4.7), feature "diffs" que actualiza solo lo cambiado.

Pricing 2026: Free (1M tokens/mes, 300K/día), Pro $25/mes (10M tokens, sin límite diario, rollover de tokens hasta 2 meses desde julio 2025), Teams $30/usuario/mes.

Bolt Cloud en 2026 ya incluye DB, auth, storage y hosting; cerró buena parte del gap con Lovable.

### Replit Agent

Sigue vivo y consolidado en el segmento "deploy todo desde el navegador". Replit fue de los primeros en adoptar Opus 4.7. Útil cuando quieres prescindir de setup local por completo.

### Comparativa rápida v0 vs Lovable vs Bolt

- **v0** → mejor calidad puramente UI (React + shadcn). Token-based.
- **Lovable** → mejor experiencia full-stack con Supabase. Créditos predecibles.
- **Bolt** → más control técnico (terminal real, modelos elegibles). Token-based con rollover.

> **Prueba esto ahora (30 min total):** replica el mismo prompt — "Dashboard de alquiler de bicicletas con lista de bicis, filtro por ubicación, mapa y panel de reservas activas" — en las tres plataformas. Compara: calidad UI, fidelidad funcional, estructura del código exportado, vendor lock-in percibido.

## Bloque 3: el flujo Figma profesional (Figma Dev Mode MCP)

Este es probablemente el cambio más importante de 2026 en este área. Si tu equipo de diseño usa Figma, este flujo sustituye en la mayoría de casos a Builder.io / Anima / Locofy.

### Figma Dev Mode MCP server

Lanzado en beta el 4 de junio de 2025 (anuncio oficial de Jake Albaugh). Servidor remoto y soporte multi-cliente añadidos posteriormente.

Da a un cliente MCP (Cursor, VS Code/Copilot, Claude Code, Windsurf, Codex, Gemini CLI, Android Studio, Replit, Warp) acceso estructurado a la selección de Figma:

- `get_code` — código generado a partir del frame seleccionado
- `get_image` — imagen del frame
- `get_variable_defs` — variables (tokens) del design system
- `get_design_context` — jerarquía, layout, props mapeados
- Skills de write-to-canvas y code-to-canvas (bidireccional)

Diferencia clave con screenshot-a-código: el LLM ve tokens (spacing, color, typography), tree de capas y component mappings. No adivina, lee. La calidad y consistencia del output es de otra liga.

Acceso: requiere Dev o Full seat en planes pagos de Figma. Free durante la beta para escritura en canvas; futuro modelo usage-based. Tier 1 REST API rate limits para Pro/Org/Enterprise; 6 tool calls/mes para View/Collab seats.

### Code Connect

Mapea componentes de Figma a componentes del codebase real (React, React Native, etc.). Combinado con MCP, hace que cuando le pides al agente "genera este frame", use tu componente `<Button>` en lugar de inventar uno. Disponible vía CLI y desde 2025 también con UI in-app.

### Figma Make

Anunciado en Config 2025, lanzado en mayo 2025. Convierte diseños o prompts en prototipos funcionales con Claude. En 2026 integra modelos de Anthropic más recientes y se conecta vía MCP al codebase del usuario.

Honestidad obligada: según LogRocket (abril 2026), el código que produce Figma Make no es production-ready: no es accesible, ni semántico, ni limpio. Útil para inspiración, prototipado, user-testing — no para shipping. Trátalo como "validación rápida" y deriva a Claude Code / Cursor para producción.

### Builder.io / Visual Copilot, Anima, Locofy

Siguen funcionando, siguen siendo válidos. Pero ya no son la única vía para Figma→React de calidad. Quedan como alternativas cuando:

- Tu equipo de diseño no tiene Dev Mode (Builder.io sigue siendo competente).
- Necesitas output multi-framework (Vue, Svelte, Qwik) desde el mismo diseño (Mitosis de Builder es único en eso).
- Trabajas en agencia y vendes el handoff como servicio (Anima/Locofy siguen ahí).

> **Prueba esto ahora (20 min):** en una cuenta Figma con Dev Mode → activa el MCP server → desde Claude Code o Cursor, conecta el MCP → selecciona un frame → pide `get_variable_defs` y luego `get_code`. Compara con lo que generaría desde una simple captura de pantalla.

## Bloque 4: MCP, AGENTS.md y el stack output (lo que cambia el juego)

### MCP como protocolo común

MCP (Model Context Protocol) fue introducido por Anthropic en noviembre de 2024 y donado a la Linux Foundation / Agentic AI Foundation (AAIF) en diciembre de 2025 junto con AGENTS.md y Goose. Hoy es el estándar de facto para conectar agentes con herramientas externas.

Para el flujo diseño-a-código, los MCP servers que tienes que conocer son:

- **Figma Dev Mode MCP** — Diseño → contexto estructurado.
- **shadcn MCP** — buscar e instalar componentes desde registries (más de 6.000 bloques en shadcn.io).
- **Chrome DevTools MCP** (Google, oficial) — DOM/CSS, performance traces, networking, console, debugging. Ideal para "¿por qué se ve así / por qué es lento?".
- **Playwright MCP** — automatización browser sobre accessibility tree, no pixel-based. Determinista, LLM-friendly.

### AGENTS.md como estándar de instrucciones

Origen: OpenAI agosto 2025 para Codex CLI. Donado al Linux Foundation en diciembre 2025. 60.000+ repos lo usaban a marzo 2026.

Soportado nativamente por: Copilot, Cursor, Windsurf, Zed, Warp, JetBrains Junie, Codex CLI, Jules (Google), Gemini CLI, Amp, Devin, Aider, Goose, Augment, Builder.io, RooCode.

> ⚠ **Excepción notable:** Claude Code aún usa CLAUDE.md y no parsea AGENTS.md por defecto. Para proyectos que usan ambos agentes, lo más cómodo es referenciar uno desde el otro.

Buenas prácticas (estudios de Princeton + ETH Zurich, 2025-2026):

- Ficheros human-curated mejoran ~4 puntos porcentuales la tasa de éxito.
- Ficheros LLM-generados empeoran los resultados (-0.5% a -2%) y suben el coste de inferencia ~20%.
- Cuanto más corto y específico, mejor. Quita secciones genéricas tipo "Architecture overview".
- En monorepos: AGENTS.md anidados; los agentes leen el más cercano al fichero editado.
- Especifica: comandos exactos de build/test con flags, versiones de dependencias, convenciones que difieren del default, ficheros que NO debe tocar.

### Stack output dominante en 2026

Casi todo lo que generan v0, Lovable, Bolt, Cursor, Claude Code, Figma Make y Copilot converge aquí:

- React 19 estable (eliminados forwardRefs en shadcn, `data-slot` en cada primitive).
- Next.js 15/16 con App Router + RSC + Server Actions.
- Tailwind CSS v4 estable (OKLCH colors por defecto, `@theme` directive).
- shadcn/ui como librería de referencia.
- TypeScript por defecto.

shadcn como ecosistema:

- **shadcn CLI v4** (marzo 2026): scaffolding completo (Next.js, Vite, TanStack Start, React Router, Astro, Laravel) con Radix o Base UI como primitivas.
- **shadcn/skills** (marzo 2026): da al agente contexto sobre los componentes y la API correcta. Activa cuando detecta `components.json`. Reduce dramáticamente los "Frankenstein components".
- **Presets:** empaquetan colores, tema, tipografía, radios, fuentes en código corto.
- **Registry** (`registry:base`): distribuye un design system completo en una sola instalación.

### Loop visual: Playwright MCP + Chrome DevTools MCP

El workflow recomendado en 2026 combina ambos:

- **Playwright MCP:** opera sobre accessibility tree → determinista, sin necesidad de modelo de visión. Bueno para interacciones (click, fill, navigate) y validación a11y.
- **Chrome DevTools MCP:** 26 tools en 6 categorías (DOM/CSS, performance, networking, console, debugging, snapshots). Ideal para diagnóstico profundo.

Para visual diff explícito: Playwright + pixelmatch + pngjs. Cursor 3 ya integra browser tool in-editor para muchos de estos casos sin MCP externo.

Ciclo automatizable: agente genera código → ejecuta Playwright → toma screenshot → compara con baseline → ajusta código → vuelve a comparar. Cierra solo.

## Bloque 5: prompt engineering aplicado a frontend (revisado)

Las recomendaciones clásicas siguen siendo válidas, pero hay un cambio de marco: en 2026 hablamos menos de "prompt engineering" y más de harness engineering (término popularizado por Mitchell Hashimoto y formalizado por OpenAI en febrero de 2026).

La idea: los humanos diseñan el harness (gates, verificaciones, contexto, AGENTS.md, MCP, tests), los agentes ejecutan dentro de él. No es "mejor pregunta = mejor respuesta"; es "mejor entorno = agente capaz de auto-verificarse".

Recomendaciones concretas para frontend con IA:

- **Contexto antes que pregunta:** pasa el `components.json`, los design tokens, el AGENTS.md, los archivos relevantes. Un agente ciego inventa.
- **Iteración incremental:** divide tareas grandes. "Crea un marketplace" falla; "crea la página de listado de productos con filtros por categoría y orden por precio, usando los componentes Card y Filter del proyecto" tiene mucho más éxito.
- **Multimodalidad bien usada:** sube capturas, frames de Figma, PDFs de spec. Pero recuerda: un Figma node-link vía MCP es siempre mejor que una imagen porque le da tokens estructurados.
- **Especificar lo que NO quieres:** "No uses librerías de UI distintas a shadcn/ui", "No introduzcas dependencias nuevas", "No toques los archivos en `/src/lib/auth`".
- **Validar en loop:** Playwright + pixelmatch o Chrome DevTools MCP para que el agente compruebe su propio output sin que tú abras el navegador.
- **Articula problemas con concreción:** "el botón se sale del contenedor en mobile breakpoint `sm:`" es 10× más útil que "el botón está mal".

## Limitaciones honestas (cuándo NO usar generación automática)

Esto es lo que las landings no te cuentan. Internalízalo y úsalo en code reviews:

- **Auditoría de seguridad estricta:** el código AI-generated introduce 10× más security findings que en diciembre 2024 (informe Apiiro, septiembre 2025). Forzar SAST y revisión humana.
- **Accessibility / legal compliance:** Figma Sites/Make y la mayoría de plataformas vibe-coding generan output inaccesible por defecto. WCAG no se garantiza sin auditoría.
- **Mantenibilidad a 12-24 meses:** los outputs de Lovable/Bolt están optimizados para velocidad inicial, no para refactor. Hay que exportar a GitHub y pasar por Cursor/Claude Code para producción seria.
- **Design systems complejos sin Figma + Code Connect:** la IA inventa props, mezcla librerías, hallucina APIs. Sin shadcn/skills o equivalente, el output es Frankenstein.
- **Coste de inferencia en agentes:** GitHub pausó signups en abril 2026 por overconsumo agéntico. Workflows agénticos consumen 10-20× más compute que autocomplete. Token-based pricing hace los costes menos predecibles.
- **Pixel-perfect contra diseño concreto:** el loop visual cierra el gap, pero no al 100%. Para hero sections con identidad fuerte, sigue ganando un dev humano con sensibilidad.
