## 1. Introducción
Ya hemos visto infinidad de casos de uso donde las herramientas de generación de código impulsadas por IA, como GitHub Copilot, Cursor o CodeGPT, aceleran los tiempos de entrega a un ritmo y coste que eran impensable hace solo unos años.

Sin embargo, como muchos desarrolladores han experimentado, y muchas investigaciones académicas ha confirmado, el código generado por IA a menudo incluye bugs y errores, así como problemas de legibilidad, mantenibilidad y seguridad. Exactamente igual que el código que generamos los humanos.


# RISKS AND CHALLENGES OF AI-GENERATED CODE

## Reliability

Code contains errors, bugs, or inefficiencies

## Security

Code contains vulnerabilities that, when exploited, result in malicious software attacks

## Maintainability

Code that is difficult to read, understand, and change prevents ease of enhancement

## Technical Debt

AI prioritizes syntax correctness over efficiency, leading to churn and complexity that is costly to repair
 

Es por eso que en esta nueva era de la programación, aumentada por IA, será crucial dedicar más tiempo al análisis del código generado. La fase de revisión del código, casi al final del ciclo de desarrollo, será fundamental para prevenir todos estos problemas.

El principal problema es que, con la democratización de los asistentes IA, se espera un aumento exponencial en la cantidad de código generado, y por tanto en la cantidad de código potencialmente erróneo o dañino que acabará en producción.


 

## 2. Herramientas IA para optimizar pull requests y code reviews
Ya hay herramientas dedicadas específicamente a garantizar la calidad y la seguridad del código antes de llegar a producción, desde el propio IDE hasta el despliegue, como SonarQube.

Cada vez más asistentes de código incluyen funcionalidades explícitas para revisar el código creado antes de publicarlo en el repositorio.

Aquí algunos ejemplos:
### Github Copilot
En las versiones corporativas, y gracias a su integración con las diferentes herramientas de Github, Copilot proporciona Pull Request summaries. Tal y como se explica en su web, “te permite crear un resumen de los cambios realizados en un Pull Request, indicando qué archivos se ven afectados y en qué aspectos debe centrarse un revisor al realizar su revisión.”

Referencia: 🔗 Responsible use of GitHub Copilot pull request summaries - GitHub Docs

### Cursor
Su función AI-Review se apoya en el git-diff para explicar los cambios realizados. Puedes optar entre revisar todos los cambios no commiteados, revisar las diferencias respecto a la rama main, o revisar el último commit realizado

Referencia: 🔗 Cursor - Build Software Faster

### CodeRabbit
Es una plataforma impulsada por inteligencia artificial diseñada para transformar el proceso de revisión de código, proporcionando comentarios contextuales en tiempo real sobre las solicitudes de extracción (pull requests) en cuestión de minutos.

## 3. Beneficios
¿Cuál es el impacto de utilizar IA en esta parte final del proceso de desarrollo?

Estas son algunas de las funciones más relevantes:

### Detección automática de problemas
pueden realizar análisis estáticos y dinámicos del código modificado para identificar problemas potenciales, desde errores comunes de sintaxis, a vulnerabilidades de seguridad, como credenciales expuestas o manejo inseguro de formularios, o posibles problemas de rendimiento como variables no usadas o bucles ineficientes. Esto permite corregir estos problemas antes de que lleguen al revisor humano, reduciendo el ciclo de feedback y aumentando la calidad entregada.

### Sugerencias inteligentes de refactorización
No es solo que detecten los problemas, también pueden sugerir mejoras o refactorizaciones, basadas en mejores prácticas y patrones comunes. Algunos asistentes incluso pueden incorporar la mejora automáticamente. Esto no solo facilita la resolución, también educa a los desarrolladores en tiempo real, y facilita la discusión entre miembros del equipo.

### Generación de resúmenes y descripciones
pueden generar automáticamente descripciones detalladas de pull requests, resumiendo los cambios realizados, identificando los componentes afectados y sugiriendo información relevante para los revisores. Incluso pueden generar comentarios automáticos para resaltar posibles problemas o sugerir mejoras. Esto ahorra tiempo en una tarea de muy bajo valor y poco satisfactoria, y asegura que todos los pull requests tengan una explicación clara y consistente.

### Análisis contextual y comparación inteligente
Pueden ofrecer análisis contextuales del código propuesto, destacando los cambios más significativos, sugiriendo áreas de enfoque principales, y ofreciendo comentarios automáticos sobre ciertos aspectos. Además, en lugar de simplemente mostrar diferencias línea por línea, algunos asistentes avanzados pueden interpretar cambios a nivel semántico, ayudando a los revisores a entender mejor la intención detrás de un cambio, incluso si el cambio involucra reestructuraciones complejas del código. Toda esta información permite que los revisores entiendan los cambios rápidamente y con menor esfuerzo, y concentren su atención en las áreas más críticas.


 

## 4. Conclusión
En estos ejemplos se pone de manifiesto que el uso de asistentes tanto a la hora de entregar el código por parte de los desarrolladores, como en la posterior revisión por sus compañeros/as, es muy relevante:

### Revisiones más rápidas y de mayor calidad:
Al automatizar muchas de las tareas de revisión y análisis, y ofrecer información detallada y precisa, los pull requests pueden ser revisados más rápidamente, lo que a su vez acelera el ciclo de desarrollo y la entrega de características. Además, el histórico queda mucho mejor detallado (esto también es documentación!), facilitando a futuro la colaboración y la resolución de posibles problemas.

### Reducción del sesgo humano
Las revisiones ofrecidas por estos asistentes son impersonales y objetivas, ya que están basadas en reglas y un análisis objetivo del código, lo que ayuda a mitigar sesgos personales que pueden influir en las revisiones humanas, tales como preferencia por ciertos estilos o prejuicios sobre la competencia de un desarrollador.

### Facilitación del aprendizaje continuo y autónomo
Al ofrecer sugerencias de refactorización, mejoras y explicaciones detalladas sobre problemas detectados, los asistentes actúan como herramientas educativas, ayudando a los desarrolladores a mejorar continuamente sus habilidades y conocimientos sin depender tanto de compañeros más senior cuyo tiempo es muy valioso.

### Mayor satisfacción
Esta fase del desarrollo es percibida por lo general como poco satisfactoria y desmotivadora. La automatización de ciertas tareas, sobre todo la de documentar, alivia esta sensación y permite a los developers centrarse en tareas de mayor valor y más gratificantes. Para muestra, un botón:
